# Subscription Tracker

Консольное приложение для учёта и управления регулярными подписками и
автоматическими платежами. Реализовано на **C++17** в рамках лабораторной
работы №3 / №4 / №5 (дисциплина — ООП / стандартная библиотека STL).

## Возможности

Все требования технического задания закрыты, плюс реализован бонус
«подключение SQL» (+3 балла).

### Управление данными (CRUD)
* добавление подписки с уникальным идентификатором;
* редактирование существующих записей;
* удаление по **ID** или по **названию сервиса**;
* **валидация**: стоимость `> 0`, цикл из допустимого перечня, дата
  следующего платежа в формате `YYYY-MM-DD` (включая проверку
  високосного года), непустые строки, уникальный ID;
* ошибки ввода **не приводят к аварийному завершению** — программа
  сообщает о проблеме и предлагает ввести значение заново.

### Поиск и фильтрация
* по **названию сервиса** — частичное совпадение, регистронезависимо;
* по **категории** (Развлечения / Софт / Обучение / Коммунальные / Другое);
* по **диапазону стоимости** `min..max`;
* по **диапазону даты** `от..до`;
* по **статусу** (active / paused / cancelled);
* возможна **комбинация** всех критериев одновременно.

### Сортировка
* по стоимости за период — возрастание / убывание;
* по дате следующей оплаты — возрастание / убывание;
* по алфавиту названия сервиса (А-Я / Я-А).

### Аналитика
* суммарные ежемесячные расходы по **активным** подпискам (с учётом
  нормализации `daily / weekly / monthly / quarterly / yearly` → ₽/мес);
* список подписок с оплатой **в ближайшие 7 дней**;
* **топ-3 категории** по суммарной месячной стоимости активных.

### Работа с файлами
* **автоматическая загрузка** `data/subscriptions.txt` при старте
  (если файл отсутствует — приложение стартует с пустым набором);
* **ручное сохранение** по команде пользователя;
* формат строки:  
  `id|service_name|category|monthly_cost|billing_cycle|next_payment_date|status`
* запись выполняется **атомарно** через временный файл и `rename`,
  чтобы не потерять данные при крэше.

### Интерфейс
* консольное текстовое **меню с циклической навигацией** (повторно
  выводится после любого действия);
* корректное отображение **кириллицы** в Windows — на старте
  вызывается `SetConsoleOutputCP(65001)` (UTF-8);
* приятные понятные сообщения об ошибках на русском.

### Бонус: SQL (+3 балла)
* В коде присутствует `SqlRepository` — реализация интерфейса
  `IRepository` поверх **SQLite** (транзакционная запись, валидация
  на стороне БД через `CHECK (monthly_cost > 0)`);
* задействуется при сборке с `-DSUBSCRIPTION_TRACKER_WITH_SQLITE=ON`
  и запуске с флагом `--sql`.

## Стиль кода

Используется **Google C++ Style** с элементами C++ Core Guidelines
(`std::string_view`, `enum class`, `std::optional`, RAII, правило
нуля/пяти). В Google-варианте расставлены `//` комментарии над
каждой нетривиальной сущностью. Код собирается без предупреждений
при `-Wall -Wextra -Wpedantic` и при `/W4`.

## Сборка

### CMake (кросс-платформенно)
```bash
cmake -S . -B build
cmake --build build --config Release
# запуск
./build/SubscriptionTracker                  # Windows: .\build\Release\SubscriptionTracker.exe
```

С бонусом SQL:
```bash
cmake -S . -B build -DSUBSCRIPTION_TRACKER_WITH_SQLITE=ON
cmake --build build --config Release
./build/SubscriptionTracker --sql
```

### MSVC (Visual Studio 2022)
Открыть `SubscriptionTracker.sln` и собрать `Release|x64`.  
После сборки папка `data/` автоматически копируется рядом с `.exe`
(post-build step).

## Аргументы командной строки

```
SubscriptionTracker [--sql] [--file PATH] [--data-dir DIR] [--help]
```

| Флаг         | Назначение                                    |
|--------------|-----------------------------------------------|
| `--sql`      | Использовать SQLite вместо TXT                |
| `--file`     | Путь к файлу данных (txt или db)              |
| `--data-dir` | Каталог данных (по умолчанию `<exe>/data`)    |
| `--help`     | Справка                                       |

## Хранение данных

По умолчанию — текстовый файл `data/subscriptions.txt` с разделителем
`|`. Строки, начинающиеся с `#`, и пустые строки игнорируются. Сломанные
строки выводят предупреждение в `stderr`, но **не прерывают** загрузку
остальных данных.

Пример записи:
```
sub-001|Яндекс Плюс|software|299|monthly|2026-07-15|active
```

## Тестовые данные

В `data/subscriptions.txt` лежат 15 подписок разных категорий
(Яндекс Плюс, Spotify, Netflix, ChatGPT Plus, Stepik Pro, Coursera,
Notion Plus, ЖКУ, VK Музыка, Adobe CC, YouTube Premium, DomClick,
Notion Calendar, Amediateka, Skillbox) и статусов (active/paused/cancelled)
для быстрой демонстрации аналитики.
